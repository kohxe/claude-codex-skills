# UI 인디케이터 이름 사전 + 구현

로딩 막대라고 다 같은 이름이 아니다. 이름을 정확히 말해야 디자이너·개발자·AI가 원하는 걸 만든다.
"로딩 막대 넣어줘"라고 하면 AI는 보통 업로드용 프로그레스 바를 만드는데, 사용자가 원한 건 글 읽기용 스크롤 진행 바였을 수
있다. 이 스킬은 (1) 애매한 설명을 정확한 이름으로 바꾸고, (2) 그 요소를 접근성까지 맞춰 실제로 구현한다.

## 들어 있는 것

| 경로 | 언제 읽나 |
|---|---|
| `references/indicators.md` | 구현하거나 자세히 설명할 때, **해당 인디케이터 섹션만** 읽는다 (정의, 쓸 때/말 때, 구조, 상태, 접근성, 흔한 실수, 코드) |
| `assets/indicators-demo.html` | 9종이 모두 실제로 동작하는 데모. 구현 코드를 가져오거나 사용자에게 한눈에 보여 줄 때 |

## 9가지 한눈에

| # | 이름 (한 / 영) | 사람들이 이렇게 말함 | 무엇을 알려 주나 | 대표 예시 | 접근성 핵심 |
|---|---|---|---|---|---|
| 01 | 프로그레스 바 / Progress bar | 로딩 막대, 진행 막대, 게이지 | 작업이 얼마나 끝났는지 | 파일 업로드, 설치 | `role="progressbar"` + `aria-valuenow` (또는 `<progress>`) |
| 02 | 스텝 인디케이터 / Step indicator (Stepper) | 1-2-3 단계 표시, 단계 동그라미 | 여러 단계 과정 중 지금 어디인지 | 회원가입, 결제, 신청서 | `<ol>` + `aria-current="step"` |
| 03 | 페이지 인디케이터 / Page indicator (Page control, Dots) | 점 여러 개, 캐러셀 점 | 넘기는 화면 중 몇 번째인지 | 온보딩, 이미지 캐러셀 | 점마다 "3번째 슬라이드" 라벨 + `aria-current` |
| 04 | 스토리 바 / Story progress (Segmented progress) | 인스타 스토리 위 조각 막대 | 콘텐츠 묶음의 순서 + 지금 것의 남은 시간 | 인스타·페북 스토리 | **일시정지** 수단 필수 (자동으로 넘어가므로) |
| 05 | 스크롤 진행 바 / Scroll progress (Reading progress) | 글 읽을 때 위에서 차오르는 선 | 글을 얼마나 읽었는지 | 블로그, 뉴스 기사 | 장식이라 `aria-hidden="true"` (스크롤바가 이미 정보 제공) |
| 06 | 원형 진행률 / Progress ring (Circular progress) | 동그랗게 차오르는 로딩, 도넛 | 진행률을 좁은 공간에 | 다운로드 버튼, 운동 링, 타이머 | `role="progressbar"` + 가운데 숫자 |
| 07 | 강도 표시기 / Strength meter (Password strength) | 비밀번호 칠 때 칸 차는 거 | 입력값의 품질·강도 | 비밀번호 생성 | 텍스트 등급을 `aria-live`로, **색만으로 전달 금지** |
| 08 | 탭 인디케이터 / Tab indicator (Active indicator) | 탭 밑 밑줄, 움직이는 밑줄 | 지금 선택된 탭 | 앱 상단 탭, 세그먼트 | `role="tablist/tab"` + `aria-selected`, 화살표 키 이동 |
| 09 | 홈 인디케이터 / Home indicator | 아이폰 맨 아래 가로 막대 | 스와이프로 홈 가는 손잡이 (OS 요소) | iOS, 최신 Android 제스처 바 | **직접 만들지 않는다** — `env(safe-area-inset-bottom)`으로 피한다 |

## 헷갈리는 쌍 — 이름을 고를 때 이 질문으로 가른다

- **프로그레스 바 vs 스크롤 진행 바 vs 스토리 바**: 시스템 작업이 끝나 가는 정도인가(프로그레스 바), 사용자가 읽은 위치인가
  (스크롤 진행 바), 콘텐츠 여러 개가 시간에 따라 자동으로 넘어가는가(스토리 바)?
- **스텝 인디케이터 vs 페이지 인디케이터**: 순서가 의미 있고 단계마다 할 일이 있는가(스텝), 아니면 대등한 화면을 넘겨 보는가(페이지)?
- **페이지 인디케이터 vs 탭 인디케이터**: 같은 종류 콘텐츠 중 위치인가(페이지), 서로 다른 카테고리의 선택인가(탭)?
- **원형 진행률 vs 스피너**: 얼마나 남았는지 아는가(원형 진행률, determinate), 모르는가(스피너, indeterminate)?
- **강도 표시기 vs 프로그레스 바**: 값의 품질을 재는가(meter), 시간에 따른 완료인가(progress)? HTML도 `<meter>`와 `<progress>`로 나뉜다.
- **홈 인디케이터**: 우리가 그리는 게 아니라, 우리 UI가 가리지 않도록 **피해야 하는** 것이다.

## 이웃 용어 — 인디케이터와 자주 섞이는 것들

| 이름 | 사람들이 이렇게 말함 | 차이 |
|---|---|---|
| 스피너 / Spinner (Activity indicator) | 빙글빙글 도는 로딩 | 끝을 모르는 대기. 진행률 없음 |
| 불확정 프로그레스 바 / Indeterminate progress bar | 왔다갔다 하는 막대 | 막대 모양이지만 진행률을 모를 때 |
| 스켈레톤 / Skeleton screen | 회색 박스가 깜빡이는 로딩 | 콘텐츠 자리를 미리 보여 주는 플레이스홀더 |
| 배지 / Badge | 빨간 숫자 점 | 알림 개수·상태. 진행과 무관 |
| 페이지네이션 / Pagination | 1 2 3 … 다음 | 목록의 페이지 이동 컨트롤. 점(페이지 인디케이터)과 다르다 |
| 브레드크럼 / Breadcrumb | 홈 > 카테고리 > 상품 | 사이트 계층 경로. 스텝 인디케이터와 다르다 |
| 토스트 타이머 바 / Toast timer | 알림 아래 줄어드는 선 | 자동 닫힘까지 남은 시간 |
| 당겨서 새로고침 / Pull-to-refresh indicator | 끌어내리면 도는 것 | 새로고침 제스처 피드백 |

## 작업 흐름

### A. "이거 뭐라고 해?" — 이름 찾기
1. 위 표에서 찾는다. 답은 **한국어 이름 / 영어 이름** + 한 줄 정의 + 헷갈리기 쉬운 이웃과의 차이 한 줄.
2. 설명이 두 후보에 걸치면(예: "위에 차오르는 막대" → 프로그레스 바? 스크롤 진행 바?) 위의 가르는 질문 하나만 던진다.
3. 영어 이름은 검색·AI 프롬프트·디자인 시스템 문서(Material, Apple HIG)에서 그대로 통하는 걸 준다.
4. **사용자가 길이를 정했으면 그 안에서 끝낸다.** "한두 줄로", "짧게", "한 문장으로"라고 했으면 답 전체가 그 길이다.
   이름(한/영)과 이웃과의 차이를 한 줄에 함께 넣고, 요청 문장을 원했으면 그 문장만 덧붙인다. 표·소제목·구현 팁·코드는
   사용자가 더 물을 때 준다. 이런 답은 대개 요청서·티켓·메신저에 그대로 붙여 쓰므로, 길면 사용자가 다시 잘라야 한다.
   - 예: "인스타 스토리 위에 있는 막대 뭐라고 해? 한 줄로" →
     **스토리 바(Story progress bar)** — 업로드용 프로그레스 바와 달리, 여러 콘텐츠가 시간 따라 자동으로 넘어가는 순서를 보여 주는 조각 막대예요.

### B. "만들어 줘" — 구현
1. `references/indicators.md`에서 해당 섹션을 읽는다. 데모 코드는 `assets/indicators-demo.html`의 같은 번호 섹션에 있다.
2. 사용자의 스택(React, Next.js, Vue, Tailwind, 순수 HTML)에 맞게 옮기고, 색·크기는 사용자의 디자인 토큰으로 바꾼다.
3. 다음은 빠뜨리지 않는다 — 시각적으로만 보이는 인디케이터는 스크린리더 사용자에게 존재하지 않는 것과 같기 때문이다:
   - 의미에 맞는 HTML/ARIA 역할과 현재 상태(`aria-valuenow`, `aria-current`, `aria-selected`)
   - 색만으로 상태를 전달하지 않기 (텍스트·아이콘 병행)
   - 화면 내용이 바뀌는 것(스텝의 다음/이전)은 바뀐 뒤 키보드 포커스를 새 단계의 제목이나 첫 칸으로 옮기기
   - 자동으로 움직이는 것(스토리 바, 자동 캐러셀)은 멈출 수단
   - `prefers-reduced-motion`에서 채워지는 애니메이션은 즉시 반영
4. 구현했으면 브라우저로 열어 키보드로도 조작해 보고 결과를 말한다.

### C. 문서·회의·AI 프롬프트용 문장
정확한 이름 + 위치 + 동작 + 상태를 한 문장에 담는다. 그대로 복사해 붙일 수 있게 따옴표 안 한두 문장으로 주고,
앞뒤 설명은 붙이더라도 한 줄 이내로 줄인다 (A-4의 길이 규칙이 여기에도 적용된다). 예:
- "결제 플로우 상단에 4단계 **스텝 인디케이터(Step indicator)**를 두고, 완료 단계는 체크, 현재 단계는 강조해 주세요."
- "블로그 글 페이지 최상단에 3px **스크롤 진행 바(Reading progress bar)**를 브랜드 색으로 고정해 주세요."
- "온보딩 3장 캐러셀 아래에 **페이지 인디케이터(dots)**, 현재 점은 길쭉한 알약 모양으로."
- "회원가입 비밀번호 입력 아래에 4칸 **강도 표시기(Password strength meter)**와 '약함/보통/강함/매우 강함' 텍스트."
- "하단 고정 버튼은 iPhone **홈 인디케이터** 영역을 피하도록 `padding-bottom: env(safe-area-inset-bottom)`을 주세요."
